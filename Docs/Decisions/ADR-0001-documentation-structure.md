# ADR-0001：现状、方案和变更记录的维护结构

- 状态：accepted
- 日期：2026-10-17
- 关联：[文档基线变更](../Changes/CHG-20261017-001-documentation-baseline.md)

## 背景

项目已有背包、武器、连击、敌人的长篇设计稿，但计划、历史代码片段与当前行为混在一起。AI 后续开发需要快速定位现状，并留下可验证的修改和接口记录。

## 决策

用 Architecture、Systems、Interfaces 记录当前事实；Plans 记录目标方案；Changes 追加每次修改与实际验证；Decisions 留存长期选择。根 AGENTS.md 是 AI 维护入口，modules.json 提供机器可读路由，编辑器快照保留特定日期的资产证据。

接口采用稳定 ID，源码只通过链接和符号定位，不复制整份实现。文档检查脚本仅检查文件和索引关系，避免将文本检查宣称为玩法验证。

## 方案比较与后果

单一大文档修改容易、查找和更新成本高；仅自动生成 API 列表能反映签名，却无法描述失败副作用、蓝图和配置契约。因此采用分层现状页 + 人工维护契约 + 简单索引校验。代价是每次实质变更要同步相关现状页与记录索引。

原设计稿作为历史参考保留。若将来引入正式文档生成、CI 或多模块架构，应新增 ADR 并说明替代关系。
