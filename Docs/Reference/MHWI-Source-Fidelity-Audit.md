# MHWI：武器动画与原生时序完整性调查

- 日期：2026-10-23 开始，2026-10-24 继续。
- 状态：源文件静态审计及 UE 正式资产只读核对完成；本轮没有修改正式动作、武器挂点或 Content。
- 关联：[调查方案](../Plans/PLAN-20261023-001-mhwi-source-fidelity.md)、[当前运行模组](../Systems/MHWI-LongSword.md)、[本轮记录](../Changes/CHG-20261024-001-mhwi-source-fidelity-audit.md)。

## 结论

源文件能提供远多于现有模组采用的动画、事件与派生条件。武器资源确有独立动画，现有武器组件没有播放它们；多数招式还省略了原生连接动画。精确取消、输入接收、主动画进入帧和武器交接规则则依赖原生运行逻辑，不能仅靠“有一条轨道/一个标志位”宣布已经解码。

现有模组通过的行为测试证明本项目按当前规则运作，不能作为原作逐帧一致的证据。完整还原应按本文末尾的证据阶段推进。

## 1. 武器位置：有什么数据，当前缺什么

### 独立动画确实存在

原始 `nativePC/wp/swo/mot/` 下有 8 份 LMT：四份非 `_fs` 文件合计 26 个有效动作，四份 `_fs` 为空。已提取不表示已接入；当前转换仅把武器导出为静态绑定姿态的 SkeletalMesh，UE 没有配套武器动画类。

正式 `/Game/MHWI/Blueprints/BP_MHWI_Hunter` 的 WeaponMesh、ScabbardMesh 均为 `ANIMATION_BLUEPRINT` 模式，`AnimClass=None`。`RefreshWeaponAttachment()` 只按招式/姿态选择 bone_012 右手、bone_002 上背、bone_008 左手和固定 Transform。蓝图默认比例 0.7 与固定位置在本轮只读核对中仍存在，来源是此前拟合，不是已证明的原版装备矩阵。

`wg03_00` 的六条动作主要移动武器自身 bone_002，源局部 Z 有 ±40 和过渡。swo001 的该骨对部分手柄区域蒙皮，主刀身主要为 bone_001；saya001 仅 bone_001 有蒙皮。因而“播放这六条动画”本身不足以纠正整把刀和刀鞘的位置，还需确认 swo001 使用哪个 `wg03` 家族，以及原生装备父级放置/交接逻辑。

### 源文件有明确的武器动作选择时刻

下表为猎人 TIML 的 `mWeaponMotionNo` 原始事件，帧从 0 开始；仅证明选择编号，尚未证明它等于挂点切换：

| 猎人片段 | 源帧 → 武器 MotionNo |
| --- | --- |
| 002 拔刀 | 18 → 2 |
| 003 纳刀 | 40 → 3 |
| 109 大回旋 | 128 → 0 |
| 306 特殊纳刀 | 73 → 3，80 → 0 |
| 307–311 居合系列 | 0 → 2，8 → 1 |

当前只在启动/结束动作等状态边界刷新固定挂接，没有逐帧消费这些事件。拔刀、收刀、特殊纳刀全过程共用一个父骨，是部分姿态不自然的明确实现缺口；是否正对应用户每个异常，仍需要固定姿态/多角度对照。

### 排除了“辅助骨全部漏导”这一假设

猎人 225 骨统一骨架包含 247–254，已查动作中存在相应 FCurves。247/248 与右/左腕、249/250 与脚、252 与头部轨迹接近，不能直接把这些辅助轨道命名为刀/鞘轨迹。508 个有效动作（164 太刀、318 通用、26 武器）未发现相同 bone+usage 的重复轨道；这批资源没有触发重复轨道覆盖问题。

骨号必须按 function/remap 解释，禁止套用旧 `bone_rename.py` 中其他模型的解剖名称。原始 `wp03_setting.cms` 可读取记录/浮点数，但当前没有可靠字段语义，不能把其中三元浮点或整数当成武器挂点。

## 2. 动画采样也有保真缺口

本地旧 Feuleur 导入器与参考的原生指令采样器，压缩量化、常量分量及四元数采样处理存在差异。离线核对发现个别辅助/手部骨角度差较大，另有大量较小的量化偏差。对 source frame/key 的误差不是 UE 蒙皮误差，也不能把最大异常直接推广成全身动作错位。

具体已用片段中，129/function48的源轨道角度差最高约18.7998°，173/function30约175.8053°。旧codec11/12/13会将未编码XYZ分量置零，参考sampler则保留插值基底常量。原MOD3 function与统一骨父链已对照，报告保留编号，不采用旧重命名表的部位标签；71个保护文件和源blend的前后哈希均未改变。

参考采样器的实现与范围见 [原作者说明](https://github.com/wowo-dot/mhw-anim-tools/blob/main/docs/repeated-track-support.md)。该工具本身也将装备父级放置、特殊控制读取、IK 等列为独立范围。因此下一步应先制作一条平行动画对照，保留当前 Skeleton/源文件，验证骨矩阵、根位移及刀手接触，再决定是否批量重转换 164 条动画。不能直接用新导入器覆盖全部正式资产。

## 3. 取消、输入、衔接：已经提取到什么

| 层 | 本次实际提取 | 仍未确定 |
| --- | --- | --- |
| 动作库 | 464 槽中 164 个有效动作，源帧数与循环点 | 哪些动作由原生 ActionNo 按状态选入、主段进入帧 |
| TIML | 19 类事件、1358 组、5014 轨道、8727 个关键帧；保留原始 hash/type/order/control/transition | 位域消费语义、浮点采样的原生实现和具体事件效果 |
| FSM | 90 节点、307 条有序连接及307 棵完整条件树，30 个 LinkMotion 节点 | 原生条件求值、输入历史/按住/新按/优先级、跨帧次序 |
| 输入 | 每条输入轨的帧与值、961 个输入关键帧的 transition=5 | 对应哪个按键、接收/缓存/可执行/清除，以及 bit 的真实有效区间 |
| 转向 | `mAttackAdjustAngleIndex`、`mTurnSpeed` 的源事件 | 索引对应的角度表、作用轴、输入采样与物理阶段 |
| 速度 | 173、308–311 具有实际变值曲线，保留控制/插值码 | 原程序如何计算插值、速度与技能/停帧倍率的组合 |

旧提取器只允许五类 group，本文件实际仅保留404组，遗漏954组；它还丢掉关键帧控制/插值/类型，将 FSM 条件压平成名称列表。本轮新审计保留完整数据，旧 `moveset_mapping.json` 暂作为现有制作输入保留，不把调查数据未经语义确认就写回动作资产。

本轮独立结构与正式资产比较通过16481条检查、0错误；检查包含重复的字段/偏移/来源端点，不是16481个玩法场景。30个连接节点包含32次MotionNo/Phase1引用，正式33个Montage段只匹配其中129，剩余31次引用未出现；不能将引用次数误报成31个不同动作。

输入 bit 的区间表仅是在“前一 key 值保持”假设下的候选区间。961 个 input key 的源 transition 并不是 constant=0；不能把候选区间当成原作取消帧。原序 link 已保存，不能按名字重新排序，也不能仅凭数组顺序断言原生优先级已还原。

源插值码2在公开工具中标为 QUAD，当前 `EvaluateSourcePlayRate()` 却全部线性。存在确定的元数据/实现差距；在原生插值方向和算法确认前，不能简单换成 `t*t`。只有变值曲线会受到本项影响，恒定速度曲线不能算作同等问题。

## 5. 完整还原的实施顺序与验收

以下为后续方案，尚未实施到正式玩法：

1. **制作可信的源采样基线。** 固定源文件和解析器哈希，制作拔刀/纳刀/居合/登龙/129各一条平行动画，逐源帧/子帧比较骨矩阵、根位移、循环点和缺失通道。确认大偏差骨的蒙皮影响后再批量转换。
2. **分离武器内部动画和整件装备放置。** 先确认装备→wg03家族映射，再按猎人事件编号驱动独立武器轨道；另恢复手/背/左手交接、可见性与原始尺寸。用握柄、刀鞘口和刀身参考点覆盖整个过渡，多视角保持同一姿态对照。
3. **解码原生控制。** 查 `cFSMPl_W03` 的条件属性读取、PlMotionInput位、ActionNo过程、转向索引表、变速插值和LinkMotion阶段。需要时对本机原程序进行只读静态分析或记录原游戏实际输入/状态；逐项记录版本、参数和证据，未知项不能批量猜。
4. **再扩展项目数据结构。** 目标为每条路由自己的接受/执行/缓存窗口、输入边沿/按住条件、连接片段、主段入帧、分阶段转向与武器事件轨道。保留现有执行序号/实例防旧回调边界；不让原始匿名位直接驱动业务。各值带来源、单位、置信度，项目覆盖单独存放。
5. **对原作验收，而不只跑项目自测。** 为每条连招在允许点前一帧/该帧/后一帧测试按下、按住、松开、预输入及冲突输入；记录原游戏与UE的实际动作起帧、位移、转角、武器姿态、命中/停帧和资源。覆盖空挥/命中、技能/颜色、坡地/低顶/落差、不同帧率和打断；对不一致项形成逐招清单。

完整原作还包括技能速度、停帧、物理/地形、碰撞和延迟伤害、相机、音效、刀光/特效、装备模型变体等系统；单独取得 LMT/FSM 不等于这些系统已迁移。此前用户指定的连续右键循环应作为显式项目输入覆盖保留；若未来严格采用原作键位语义，应使用独立原作配置，避免无说明地撤回已确认的操作习惯。
