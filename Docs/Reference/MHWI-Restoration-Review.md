## 判断

当前产物是**使用原作素材、具有地面太刀主要动作的训练适配器**。它具备真实资源与扣血、见切/居合防御、分段登龙和生命周期保护，但输入语义、若干派生、资源经济、攻击数据和命中空间仍有明确偏差。导入完整动画库、解出425字段、历史PIE通过，均不能推出玩法已完整还原。

问题不只是“再调几段动画”。目前部分原始数据已经正确提取，却没有被运行时消费；另一些字段被接到了错误或未证实的消费者上。应先修正行为与数据契约，再做连接、运动和表现验收。

### 不能再次误报为缺陷的现状

- `M_ForesightSlash`使用140、`M_SpiritThrust`使用170；当前映射正确，旧反置已经修正。
- 正常气刃I/II/III/回旋cost15/15/20/25及白黄红195/135/60秒已写入；R11讨论独立的暂停消费者问题。
- 见切回旋具有`RequireHit && RequireCounter`，回槽也等待实际扣血回斩；不能重新批评为“按见切就满槽开刃”。
- 居合气刃成功反击保色、失败降色的World规则已存在；没有成功自动升色。R05/R16针对额外出口和伤害模型。
- 已有分离的无敌/反击半开窗口、执行序号、Montage身份、过期回调保护和分段登龙；这些应保留。
- 原6条内部武器动画/19源事件、连续握柄交接和36条平行库已经接入部分流程。CDO `WeaponMesh.AnimClass=None`不能证明它运行时没有动画，[C] `SetSourceWeaponMotion`会设AnimationSingleNode。
- 当前地图三个木桩的`enable_attacks=false`；没有本轮证据说明“练习普通招式会自伤”。
- 三色居合Montage复用Native308有既有共享骨轨证据，不因文件名相同就判错；需要独立保留颜色速度、事件和攻击定义。

### 两项需要明确的研究限度

1. 本轮没有测出原版缓存帧、完整连接入帧、每个转向角和全部反击接收类别。计划必须为这些项设取证门槛；不能为了看起来完成而填统一数值。
2. 原版衰减、回旋清槽和回气倍率另参考了[ICE原作者的原版差异说明](https://github.com/AsteriskAmpersand/Ice-Stable#long-sword)。这里只采用其中明示的原版行为，**不采用ICE的新动作值、升刃或改进派生**。原作者报告原版Q每6秒减5%、攻击重置、回气状态抑制；这些属于一手研究佐证，仍应验证本机版本的计时域和边界。该证据也支持现有6.67%/秒回气近似值，因此本轮不将其列为确定错误。
