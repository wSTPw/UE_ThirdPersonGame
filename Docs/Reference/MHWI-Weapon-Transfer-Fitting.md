## 源姿态证据

[author_weapon_transfer.py](../../Scripts/MHWI/author_weapon_transfer.py) 的 `audit_source_contacts()` 只读正式 Skeleton 和九段 Sequence，不启停 PIE、不保存资源，仅写入 `Saved/MHWIImport/WeaponTransfer-20261024/source-contacts.json`。2026-10-24 已实际执行，覆盖845个整数帧。002/003/306/307/308/110 读取 NativeFidelity 平行库；309/310/311 含 NeedsParent，仍读取原正式库，不把旧采样描述为合格原生采样。

参考点来自现有 [attachment_fit.json](../../Scripts/MHWI/attachment_fit.json)：手腕局部掌心(-7,2,0)、普通握点(0,-12,0)、特殊握点(0,-66.485203,0)、鞘口(0,21,0)。它们是项目拟合标记，不能当作原版装备初始变换。当前部件比例0.7保留。此段参考点与845帧数字是此前的离线证据，不是本次重新执行的UE检查。

| 静态发现 | 测量 |
| --- | --- |
| 旧背负姿态不能保证拔刀接触 | 002 全段右掌到旧背负握点最近25.16 cm，出现在25帧 |
| 旧背负姿态不能保证纳刀接触 | 003 最近29.06 cm，出现在52帧 |
| 旧特殊固定变换只对尾姿有效 | 306 第60/70帧右掌到特殊组件握点偏差32.9/28.6 cm；73帧约0.3 cm |
| 内部动画改变真实握柄位置 | wg03_00_003 第0至10帧将bone_002组件Y从-40移至+40，累计80 cm；其蒙皮区域沿源纵轴覆盖-78.9..9.1 |

因此，组件原点重合和静态握点接触不足以验收新版本。特殊保持时把刀、鞘原点强行重合，会忽略80 cm内部伸缩，使真正的握柄离开右手。

`audit_source_skin()` 已在只读打开原 `.blend` 的后台 Blender 中执行。普通/特殊握点周围各12个最近表面顶点的 bone_002 权重均值分别为0.149560119/0.520039097，每一组的最小/最大权重相同，其余有效影响为bone_001。结果与顶点编号保存为 `source-grip-skin.json`，`source-grip-skin-provenance.json` 确认原blend前后SHA256一致。运行时使用六个测量位置间的权重插值，把材质参考标记按两个骨的当前矩阵混合；不把整个握柄误当作100% bone_002。它是源网格支持的局部材质标记拟合，不是手掌的完整碰撞接触求解。

## 已实现的运行适配与边界

[MHWIWeaponAttachment](../../Source/IntroCpp/MHWI/MHWIWeaponAttachment.h) 是普通 C++ helper，不持有 UObject、Timer 或委托。角色在 TG_PostUpdateWork 中刷新猎人/武器姿态后传入现有骨名、五个拟合变换和当前动作位置。零Delta调用换父骨但不推进交接时钟；最终接触锁定允许调整组件原点以保持动画后材质点接触，不能等同于整件世界变换不动。正常Tick推进剩余交接。结束、打断、死亡进入相同更新路径，不遗留异步回调。

- 普通右手握柄标记从 Mesh 参考骨架转换到当前武器 bone_001/002，并使用实测蒙皮混合权重。现在在组件变换完成旋转/位置混合后再次锚定右掌，避免混合时产生握柄漂移；普通姿态从特殊纳刀中断返回时，以0.16 Actor秒转移材质握点。
- 拔刀10..25/60秒由背负过渡至右手；纳刀40..52/60秒由右手过渡至背负。25/52来自当前源姿态接近点，40同时与源内部武器事件一致。这些区间是项目拟合，未解码为原作挂点事件。
- 特殊纳刀先连续将鞘交左手，60..73/60秒按双掌轴线渐进插刀。右手始终锚定动画后的握点，左手约束鞘口。保持时刀刃与鞘口同轴，允许为维持真实握柄接触而出现轴向抽出量；不缩放剑或延长手臂。
- 居合按源0/8帧内部事件区间，从前一动作实际使用的材质握点连续转移到普通握点。剑的最终变换锁定右掌；鞘的最终变换锁定左掌。Special→Iai及居合变体之间只按真实父骨/所有权切换，不按每次ExecutionSerial重新启动鞘的0.16秒交接。
- 通用交接平滑时间0.16秒；特殊末段、普通拔纳刀区间均明确属于项目适配。

- 纳刀直接攻击使用独立的0..10/60秒整刀交接，从实际部件入口姿态过渡，不强制先回到理论背负变换；无原生事件的纳刀攻击由内部motion2从纳刀状态拔出，而不是直接切持刀静态1。它是项目适配窗口。
- 大回旋显式纳刀0号事件（当前128/60秒）作为项目收刀拟合的结束锚点，前12/60秒交到背部；不等动作结束才突然改挂点。内部动画事件仍不被解释成原生挂点指令。
- 视觉已回背但玩法标志尚未纳刀的大回旋尾部，后继动作仍能识别背部入口。记录的是动作入口的装备状态，不改变攻击许可/消耗/派生逻辑。
- StartResolvedMove的直接派生推迟内部姿态重置到后继事件/默认姿态选定，不经过可见的中间静态0/1；装配刷新在新姿态求值之后。真实结束、打断、死亡仍恢复对应默认姿态。角色Tick显式依赖猎人/武器Mesh，武器不可见时仍刷新骨姿态。

上述位置实现已落地；**用户要求本轮不做最终UE运行调试，当前视觉效果待用户验收**。未证明整刀抽出长度与原作一致。原版初始装配/IK消费者、衣物碰撞与全顶点无穿插仍没有还原依据；背负位置仍沿用项目拟合。309/310/311已通过共享骨轨证据复用Native308，详见[共享轨道实施](../Changes/CHG-20261024-003-mhwi-defense-routes-transfer.md)，不再沿用此前“正式三色待外部姿态”的现状描述。
