## R28：基础移动与过渡片段

基础循环已有独立源采样、FBX 与 225 骨架资格证据，五个移动字段和六个 BlendSpace 样本已经迁移。正式图仍由 `Speed`、拔纳刀状态和两张一维 BlendSpace 驱动；持刀 walk/run 继续共用 `w03_00_004`，180/420 cm/s 是项目样本设置，不是从原游戏消费者解出的速度阈值。

本轮用原太刀 `w03_00.lmt` 固定源文件（SHA-256 `2406ee8f61fe7ba21008f200881be6d339c93af07a9ff7ada9260f0c58a8c42b`）解析六个待核候选。每项均有 82 条 FCurve，60 fps；表中平移是 LMT action header 原始 `translation` 三元组，不将它单独解释为角色最终位移，也不从编号推断动画语义。

这六条在现有 `NativeFidelity/export-manifest.json` 中没有资格记录，角色用途也未由独立原生路由/实机捕获逐条绑定。因此目前证据能支持把这些源片段做合格采样、预览和项目过渡实现；还不能把某个 Motion 直接命名为“起步/转身/停步/落地”并声称是已证原版映射，也不能声称已得原作速度与状态阈值。

**裁决：**足以开始一个范围受限的 R28 项目动画实现方案，先资格核验、再以实测状态接入；要宣称精确原作过渡语义，还需独立动作绑定或对照捕获。台账维持“部分完成”。

## R30：装配与四条 IK 链

B17 固定源归档报告中 `hm/common/ik/` 的八项资源均与用户指定游戏归档 SHA 一致（8/8），没有对应 `nativePC` 覆盖。四个 IK 文件各 5982 字节；`hm.arm_mgr` 33 字节、`hm.leg_mgr` 212 字节、`hm.ikctrl` 142 字节、`hm_common.ctm` 592 字节。原始指纹见 B17 的[资源复验报告](../../Saved/MHWIRestoration/B17-20261026/native-parameter-fingerprint-verification.json)；本轮脚本也重算了仓库提取件的长度和哈希。

`.ik` 中已解析的索引组与 `NativeFidelity/rig-bind.json` 按编号逐一对应，并在该 225 骨架中形成连续父子链：

| 资源 | 索引 / 绑定骨 | 父子顺序 |
| --- | --- | --- |
| `larm.ik` | 6 / 7 / 8 | `bone_005 → bone_006 → bone_007 → bone_008` |
| `rarm.ik` | 10 / 11 / 12 | `bone_009 → bone_010 → bone_011 → bone_012` |
| `lfoot.ik` | 14 / 15 / 16 | `bone_013 → bone_014 → bone_015 → bone_016` |
| `rfoot.ik` | 18 / 19 / 20 | `bone_013 → bone_018 → bone_019 → bone_020` |

既有固定版本指令快照还证明：`hm.ikctrl` 有 12 个槽位、四个非空链路径；`cpIKCtrl` 更新例程在对象启用条件满足时遍历 12 个 stride `0xd0` 的槽位，并对存在的对象调用虚函数槽 `+0x48`。这些是资源布局与调用结构事实，不足以命名匿名 manager 字段或反推 solver 的目标空间、极向/限位、参考矩阵及调用参数单位。`hm_common.ctm` 保留为原始 592 字节，仍未作为挂点矩阵使用。

当前项目已经播放六条独立太刀内部动画，并由 `FMHWIWeaponAttachmentRuntime` 按项目拟合值处理刀/鞘位置、材料握点与双掌保持；`ABP_MHWI_Hunter` 没有原生 IK 节点，四条 IK 链没有运行时消费者。0.7 缩放、0.16 s 交接和掌心/鞘口点仍明确是项目拟合值。

**裁决：**骨链映射与资源来源已足够支撑一个明确标注为“项目适配”的四链 IK/装配实现方案。原生 solver 复刻仍需求解坐标/参数语义和运行状态证据；计划不把 Control Rig 或 UE 双骨求解器冒称原版算法。台账维持“取证中”，直到源语义与用户运行验收分别达标。
