## 本轮静态发现

以下为控制流推导，**均未运行复现、均未修复**。行号对应本轮源码快照，哈希见离线证据。

### A01 / P1：受击输入锁使 R06 的 Step 来源恢复派生不可达

- `MHWICharacterNativeSources.cpp:77`：成功进入小/中/大受击后设置 `ControlState=Flinch*`。
- `MHWICharacter.cpp:658` 与 `MHWICharacterNativeSources.cpp:178`：`RequestInput`、`RequestNativeSourceInput` 都因 `IsGestureLocked()` 拒绝所有输入；该谓词在头文件269行对一切非Free状态返回true。
- 同文件 `ResolveNativeSourceInput` 仍定义受击→SpiritI/StepSlash等出口，`TickNativeSource:278` 仍使用 `ImpactCancelStart`，但正常输入不能写入其 `NativeSourceInput`。
- `FinishMove` 到1315行才释放控制状态，此前已调用 `ReleaseNativeActionSource` 清来源身份及缓存。结束后从中立启动不能替代带30/31/32（或common103/110/115）身份的恢复入口。

因此B10“真实受击来源正常输入续段”的交付条件被B12阻断。R06不能继续标记开发完成；32引用中至少来源含node26的N53-P0/N60-P0/N60-P1需重开，专用入口中的受击分支也受影响，不能以这三行穷尽全部分支。修复应区分硬直锁定与合法恢复许可，保留真实来源身份；不应简单放开全部受击期命令。

### A02 / P2：按住旧组合时，无关的新按键会再次产生组合命令

`MHWICharacter.cpp:400–429` 只要求 `FrameInputEdges` 非空，随后用Held状态判组合，不要求组合成员本帧产生边沿。例如RT+Y仍按住，再按A（回避）：Edges只有Evade，但函数先请求HelmBreaker，再请求Evade。组合成员没有新边沿也会重复请求，可能先启动/切段再处理回避，或覆盖单槽缓存。R01/R08的“单手势不双发”不能据源码判通过。修复须让组合消费有明确的新边沿来源，并约束一次手势的命令提交。

### A03 / P2：原版手柄预设同时改变键鼠组合语义

`BuildInputMapping:198–222` 把键鼠和手柄映射到同一组CommandActions；`CommandStarted:383` 在预设开启时将所有设备输入交给同一组合解析器，没有设备来源。于是键盘R+鼠标左键也会被合成HelmBreaker，左右键同按会合成FadeSlash。原“开启手柄预设后键鼠不变”的文档承诺不成立。修复需保留设备来源或明确改变产品契约；本轮只纠正文档边界。

### A04 / P1：菜单阻断未撤销原生来源的待执行输入

`SetInputBlocked:432–440` 清除PendingInput/Helm请求/FrameInputEdges，却未清 `NativeSourceInput`。在弹刀或投射器来源中先缓存合法续段，然后打开菜单，`TickNativeSource:276–283` 仍可消费该缓存并调用 `StartResolvedMove`；后者入口不检查 `bInputBlocked`。因此RequestInput/StartMove虽拒绝新请求，已经排队的原生来源派生仍可执行。修复需同时覆盖来源缓存和内部提交路径。

此外 `Move:275`、`Look:362`、Sprint回调均不检查阻断位，C++检索未发现UI调用方。当前只能交付“部分动作入口的阻断接口”，不能交付完整菜单接入；蓝图调用关系本轮未重新加载核对。
