## 结论

原作太刀资源包含与攻击记录关联的独立碰撞几何参数组；太刀 LMT 中有 `CollisionTimelineObject` 轨道，轨道中的 `NodeID[0]` 可与 `wp03.col` 攻击记录的 `timeline_uid` 逐一关联。固定版原生代码区还含有 `nCollision::cGeometryJoint` 类型名及独立构造器/vtable，说明原生碰撞系统存在名为 joint-geometry 的对象类型。现有静态证据强力支持“攻击按动作时间启停、并引用武器碰撞参数”的实现路径，而不是只由角色胶囊做全程统一命中检测。

证据**不能**进一步证明这些参数是刀刃三角网格、特定半径胶囊/球体，也不能证明 `wp03.col` 的任一几何组实例化为 `cGeometryJoint`，或运行时挂到哪根骨骼、采用什么局部/世界空间变换。公开社区格式模板确认 `.col` 中存在几何组、内层参数及 `Attack_Range` 字段，但把其他绝大多数字段保留为 `Unk_*`；它是逆向格式参考，不是 Capcom 官方规范。参见 [MHW-Editor `.col` 模板](https://github.com/Synthlight/MHW-Editor/blob/master/010%20Templates/col.bt) 与其 [碰撞格式说明](https://github-wiki-see.page/m/synthlight/mhw-editor/wiki/Collisions)。

因此，对“攻击判定是不是武器上的碰撞体”可回答：**按攻击引用的原生几何参数与动画开关来看，是；若“武器上的碰撞体”特指沿可见刀刃、绑定特定骨骼的真实碰撞形状，目前证据还不足以确认。**

## 静态加载链续查与实施决策（2026-10-27）

`wp03.col` 的 `CLND` 类型原值为 1。固定版函数 `0x14191a5c0` 用该索引查 `0x143f94a18` 工厂表，再经工厂对象 vtable 的 `+8` 槽创建节点对象。表项 1 指向 PE `.data` 零填充区中的对象；静态初始化函数 `0x140009890` 为它注册名称 `cCollNodePl`、大小 `0x58` 和 vtable。`CLND` 读取函数 `0x1419c30b0` 调用新节点实例 vtable 的 `+0x28` 槽，该槽经包装函数 `0x140294530` 进入解析函数 `0x1419c2fe0`。因此，类型 1 目前只能确定为**碰撞节点工厂类**，不能解释成几何形状类型。

独立的 `nCollision::cGeometryJoint` 名称、构造器仍存在，但当前静态链没有把 `wp03.col` 的 13 组 `CLGM` 数据或其中的 72 字节记录映射到该几何类，也没有解出字段语义、骨骼索引及局部/世界变换。由此作出决策：**原作 `.col` 当前不可直接作为项目刀刃碰撞实现依据；如需继续做可用的玩法命中判定，应转为项目自己的武器/骨骼扫掠方案。** 要复用原作精确形状，仍需补上运行时对象/骨骼观测或获得可解释这些字段的额外证据。

### 几何参数能读到的层次

按社区 `col.bt` 布局解出 `CLND` 的参数类型原始值为1，包含13个 `CLGM` 组；每组内部包含不同数量的定长参数记录。几何组0的第一条参数记录，其模板命名字段 `Attack_Range=50`，其余坐标样式字段仍是模板中的未知字段。文件还有模板未命名的尾字段。

当前脚本保留原始数值字段，不把它们命名为中心点、端点、骨骼号、半径、轴向或局部坐标。没有足够的字段语义或原生运行时消费链时，单凭看似坐标的浮点数猜形状不构成取证结论。

## 对项目当前实现的对照

项目 `AMHWICharacter::SweepWindow` 目前以角色胶囊移动为基础，在高度偏移35cm处做球体扫掠，并向前及侧方扩展；它查询 `Pawn` / `WorldDynamic`。构造函数把 `WeaponMesh` 与 `ScabbardMesh` 的碰撞设为 `NoCollision`。这是一条可工作的项目攻击检测路径，但不是从原版 `.col` 几何参数逐骨重建的刀刃碰撞。

代码位置：[MHWICharacter.cpp](../../Source/IntroCpp/MHWI/MHWICharacter.cpp) 中的 `AMHWICharacter::SweepWindow` 和角色构造函数。现状说明见 [MHWI 太刀系统](../Systems/MHWI-LongSword.md)。

## 结论边界与下一步

| 问题 | 当前证据状态 |
| --- | --- |
| 原作是否存在武器攻击相关碰撞数据？ | **是**：太刀 `.col` 含攻击记录、几何组引用和UID，且动作轨道UID逐项匹配 |
| 原作碰撞是否由动作时间控制？ | **强静态支持**：39条 `CollisionTimelineObject` 轨均匹配；具体运行时开关消费者未动态观测 |
| 是否能证明是刀刃网格或特定几何体？ | **不能**：公开模板多数几何字段未知，尚未解出各字段含义 |
| CLND 类型 1 能确定什么？ | **能确定节点工厂类 `cCollNodePl`**；它不是几何形状类型，也不能据此推出骨骼绑定 |
| 是否能证明挂在刀身骨骼/Socket？ | **不能**：尚缺 `CLGM` 几何参数到碰撞运行对象、骨骼索引及空间变换的闭合链 |
| 是否能证明伤害用接触部位查肉质？ | **不能**：怪物部位选择、肉质行选择及后续伤害消费者仍未全部闭合 |
| 项目是否已实施这套原生刀刃碰撞？ | **没有**：项目当前是角色根运动驱动的球形前向/侧向扫掠 |

后续如要复用原作几何，应针对当前安装覆盖状态观测 `CLGM` 记录实际创建的几何对象及骨骼变换；当前证据支持转做项目自己的武器/骨骼扫掠命中方案。R18 仍保持取证中，因为刀刃形状、骨骼空间和肉质选择尚未闭合。
