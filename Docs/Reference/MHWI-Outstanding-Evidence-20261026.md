## R10/R11：Q与颜色是两套计时

W03P加载器`0x141379680`把资源值读入参数对象。武器更新`0x1421237b0`中，`+0x2368`为归一化Q，`+0x236c`为Q衰减倒计时；`+0x2370`为颜色、`+0x2374`为归一化颜色余量、`+0x2390`为颜色暂停秒数。武器参数访问器为`0x14211c060`。

Q更新在相关资格位成立、且登龙/居合回槽计时均未生效时：倒计时减`dt_seconds / 120`；严格小于0时重置为0.05，再从Q扣0.05并钳制。名义间隔`120 × 0.05 = 6`秒，**不是每秒扣5%**。每次更新最多扣一步，不补偿跨过多周期的余量。`0x142122410`修改Q时也重置倒计时；正收益经过技能修正、负值直接作用。两个回槽计时有效时走回槽分支，跳过上述自然衰减。

颜色基础195/135/60秒来自W03P `0x4f1/0x4f5/0x4f9`，消费者还结合技能倍率。合格回旋提交`0x142122570`执行：颜色加一并封顶3、颜色余量设1、Q设0、`+0x2390 = 参数+0x884 = W03P 0x51d = 10`、清除锁存。这里是**赋值刷新，不是累计相加**。更新器`0x142123915–0x14212395d`先递减暂停，暂停不大于0后才递减颜色余量。因此B12“10秒保留给Q抑制”的解释错误；也不能只把10秒粗加到颜色基础时长来覆盖全部刷新、收刀及技能条件。

玩家更新`0x142228f50`分别将帧增量写`actor+0x6c`、秒增量写`actor+0x68`；已有时钟链的60帧标尺和这次秒/帧消费相互对应。尚未运行验证hitstop时序，不因此认定项目应冻结哪些系统。

## R13：回旋接触锁存与一次性提交

Action69 `WP_03::KIJIN_SPIN_SLASH`入口`0x1417fe960`并不无条件清Q。接触回调`0x142123510`核对拥有者、目标资格及去重；当前Action69并满足拥有者资格位时，在`0x142123717`置`weapon+0x2cec=1`。update `0x1417ffec0`看到公共参数`+0x28 bit30`后调用提交；exit `0x1417ff130`也调用同一提交`0x142122570`。锁存为0就返回，提交后清锁存。

局部链说明：空挥不会凭退出清Q；已合格命中后若先走退出，退出路径仍尝试提交；命中前中断没有这次锁存。上游事件覆盖及动作中断排序未穷举，这些是本地链结论，未执行游戏行为验证。

## R16/R19/R31：接触计时不是hit lag

事件接收器`0x142124b20`处理合格接触（事件kind7，含拥有者核对；kind0x3b另清去重）。目标类型查询`0x141cb4fb0`返回4时被排除，还检查目标`+0x60 bit1`与`0x141cb94f0`拒绝条件。

- Action91/92调用`0x1421225e0`：首目标捕获颜色、目标/部位及相对坐标；参数`+0xa5c`（W03P `0x5f8=0.4`）写入首计时。后续计时为前一剩余计时加参数`+0xa60/+0xa64`（各0.05），上限`+0xa68=7`。更新`0x142125150`减玩家秒增量，到期经`0x141aa74a0`创建shell，并用目标当前姿态转换保存位置。队列可由单次记录的接触继续填充；跨多到期段可能同帧发出。取消/退出门控仍有未覆盖路径。
- Action102居合气刃：合格接触记录弱目标、部位/相对点，按白/黄/红选择shell12/13/14；无色为无效shell。`0x142124da0`把参数`+0x8c0`（W03P **0x54c**=0.5）写入`+0x2d20`。更新`0x142125860`按秒递减，要求仍在Action102且目标有效再生成；退出动作会清待发状态。该0.5不是登龙另一个`0x60c=0.5`字段。`+0x8bc=1.3`及反击快照下游的完整伤害叠加仍未闭合。

B12把`HelmStrike.HitLagSeconds`填0.4没有这条原生证据支持。原指令明确将其用于shell计时，不能据此冻结表现0.4秒；本批只记录R-COMBAT-018，未改正式DA、伤害窗口或代码。

## R21：普通回避13帧的消费链

Action18及其他四个方向回避共享入口`0x141784e90`→`0x141783470`→`0x141f752d0`。已核对Action18构造经基类把保护行索引`+0x38`设0；其他方向完整构造与运行覆盖继续开放。

`rPlayerParam`加载器`0x141a0e640`校验PLP版本31，再加载资源`+0xb0`的`cPlayerParam`；`0x141240740`在参数`+0x938`读10行、每行stride0x28。行加载器`0x1405f4290`连续读7个float写行`+8..+0x20`，因此资源首值位置为`0xb0 + 0x938 + 8 = 0x9f0`，对应文件`0x485`。

`0x141f752d0`查询技能0x4e并钳制0..5，六分支表在`0x141f75518`；按行选择`resource+0x9f0/9f4/9f8/9fc/a00/a04`，衣装另读`+0xa08`，存到角色`+0xe168`。这个字段保存的是浮点帧数，不能因一条`mov ecx`便当成整数。

更新`0x141f6c2fe`附近减角色帧增量并钳制0；`0x141f70035`附近检查其为正或其他保护条件，然后设置角色`+0x8948/+0x8978 bit27`与碰撞结构保护位。13/60约0.2167秒是名义持续，不代表已实测完整伤害无敌窗；消费次序、起止边界及各类伤害判定仍需核对。

## R29：3.5秒等待与motion306边界

Action98入口`0x1417fe2b0`请求motion `0xc132306`。Action99入口`0x1417fe270`不再请求新motion，读取参数`+0x8b4 = W03P 0x540 = 3.5`到动作`+0xcd0`；update `0x1417ffa50`调用公共动作更新后减玩家秒增量，过零返回完成。存在快纳刀技能分支，不能概括为所有配置恒定3.5秒动画。

原LMT entry306 header `0x3290`：82曲线、272帧、loop129；TIML length271/loop_start129。mActionPhase在73变1，mWeaponMotionNo在73为3、80为0，输入标记在65/80变化。它们证明事件存在，不能单独证明应冻结在73，也不能据Action99不请求motion便证明整个播放系统必然前进到80。完整保持/循环与事件消费链仍是R29余项。
