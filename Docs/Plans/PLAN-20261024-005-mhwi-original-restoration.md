## 现状与目标

正式运行链为：`/Game/MHWI/Maps/L_MHWI_Training` → `BP_MHWI_TrainingGameMode` → `BP_MHWI_Hunter`（原生MHWICharacter）→ `DA_MHWI_LongSword` + `ABP_MHWI_Hunter` + 29个Montage。

32招定义中包含复用身份与颜色载体，不可把它当32个原版动作已完整实现。当前149条路由也不能直接除以原FSM307边计算覆盖率；原图还包含连接、聚合和原生公共节点，两边统计单位不同。

目标是让**相同条件与语义输入产生相同的动作资格、派生、资源变化、命中、保护、运动与衔接**，并在动画、武器装配、镜头及声画反馈上逐项对照原作。基线为本机原始chunk的World/Iceborne数据；不采用Rise/Wilds或ICE的改动规则。

保留现有有效能力：独立模块边界、真实属性扣血、执行序号/Montage实例防旧回调、命中去重、分离防御窗、见切双条件回旋、World居合保色、登龙物理阶段与清理、源采样/武器内部动画。避免因还原而退回单段动画串播。

## 技术方案

### 1. 原始数据、语义规则与正式资产分层

建立唯一生成入口，例如拟新增`Scripts/MHWI/build_reference_profile.py`，分三个输入层：

1. **原始层**：LMT/FSM/W03P/COL/shell/公共参数及版本/哈希/偏移。保留原序、条件树、插值/控制值、UID；原文件只读。
2. **已确认语义层**：动作/攻击变体、输入条件、资源提交、取消、保护、运动/装备事件与证据。每个转换规则必须有单位、消费者、来源、可信度和未解项。
3. **项目适配层**：UE坐标转换、碰撞近似、可选快捷键、尚未证实的拟合。明确命名、独立开关，不得覆盖原始层而丢掉真实数值。

生成过程先预览差异；发现手改字段、未知消费者或不匹配的源指纹即报告并保留旧值。成功后保存候选DA并逐项读回。连续生成两次结果应一致；不能再依赖“先基础制作、再按某个顺序打几个补丁”才能恢复正确资产。

建议候选路径（**拟新增，当前不存在**）：

- `/Game/MHWI/Data/Restoration/DA_MHWI_LongSword_Reference`
- `/Game/MHWI/Blueprints/Restoration/BP_MHWI_Hunter_Reference`
- `/Game/MHWI/Animations/NativeFidelity/LongSword/`补缺少的合格连接Sequence
- 独立验证地图放在`/Game/MHWI/Maps/Restoration/`；最终验收后再迁移正式训练入口。

保留`/Game/MHWI/Data/DA_MHWI_LongSword`及原Pawn作为迁移前对照。旧适配预设可供回归，但界面和报告必须标“项目适配”，不能冒称原版模式。

### 2. 调度与数据契约

继续以`AMHWICharacter`作为外部动作入口；在`Source/IntroCpp/MHWI`内逐步拆出可单独验证的输入仲裁、资源、时间轴与命中实例结构。初期不强制改成大量UActorComponent，也不接入旧Ninja动作管理器。

`MHWIMovesetData.h`的扩展方向：

| 数据 | 必须表达的内容 |
| --- | --- |
| 输入记录 | 设备/物理边沿、按住集合、输入序号、时间戳、方向快照、组合消费归属 |
| 路由 | 源node/condition ID、原顺序、完整条件、接收/缓存/执行窗口、连接过程、目标主段入帧、`bEnabled`与证据状态 |
| 动作实例 | 自己的执行序号、ActionNo、MotionNo/阶段、颜色/槽/攻击快照、资源提交记录、命中/反击结果 |
| 攻击定义 | 近战/shell记录ID、MV及条件替换、物理/属性/异常/部位/软化/骑乘参数、碰撞几何、时序、停顿、去重策略 |
| 资源效果 | Q、C、T、耐力、衰减计时/抑制和各回气效果分开；来源、刷新/覆盖、到期与时钟 |
| 延迟实例 | 独立effect ID、来源动作、目标/部位或空间锚点、参数快照、触发原点、分段进度、取消/失效策略 |
| 证据 | 原文件哈希/偏移/字段、公开一手来源或录像位置、变换公式、确认等级、尚未解释的原字段 |

不可把所有输入最终压成“最后一个EMHWIInput”。一次组合输入只授权一次动作；同一物理按键可以作为按住修饰符，不要求R与A必须同帧按下。

不删除已有执行身份保护。通知、Montage回调、延迟命中、落地和伤害回调都带来源序号；状态变更在游戏线程安全边界提交。独立延迟实例不得依赖已经销毁的裸Actor或Component指针。

### 3. 输入与派生修正

原版手柄配置使用Y/B/RT/A以及相应组合，键鼠经过同一语义层。专用见切/居合/登龙快捷键可以作为可选辅助配置保留，但要合成相同原子语义命令并遵守相同资格，不能额外赋予非法出口。

按源节点自己的有序条件仲裁，特别检查同时输入Y+B、RT+B、RT+Y、RT+A时，组成它们的单键不会先发出另一招。长按/重复/松开、同帧移动与按键、按键跨帧顺序均保留记录。组合容差和缓存时长依证据填写，不另拍脑袋规定统一毫秒值。

先修正已有确定错误：

| 路线 | 目标 |
| --- | --- |
| 普通突刺后 | A接上挑；原版配置删除新增B无限循环。上挑B回突刺仍按原条件保留 |
| 三袈裟后 | A/B接突刺；R接气刃踏步，再R接III；恢复左右选择与连接 |

`9999秒`表示禁止的哨兵值迁移为`bEnabled=false`；缺省窗口与显式关闭不能混淆。完整FSM条件表达式需要保留，未知原生条件不能自动按true处理。

### 4. 资源与攻击数值

**先处理Q/C/T，后扩复杂伤害**：

- 气刃踏步cost由12改为20；正常气刃15/15/20/25保留。弱气刃I保持原有14/26分支，不将18/28的气刃踏步条件替换混进同一规则。
- 恢复Q自然衰减。源量0.05直接保留；一手研究给出的6秒/攻击重置/回气抑制为可核查候选行为，原版版本、起算和低帧补算确认后进入正式配置。
- 将10秒Q衰减抑制与T颜色计时拆开。不得继续直接借该字段暂停T；T使用195/135/60并独立规定起算、刷新、降级和颜色消费。若存在另外的T暂停，必须独立提供证据。
- 回旋增加“剩余槽清空”事件，和25启动资格分开；清空何时提交、空挥和被打断如何处理要先核对。不能简单在每次`FinishMove`里无条件清空。
- 普通命中回槽按COL基值恢复，保留命中/肉质/技能修正消费者。现有6.67%/秒和15/30/10/15秒回气效果有一手研究支持，继续验证刷新和覆盖规则，不因原始字段名模糊而随意改掉。
- 建立耐力：回避原始25和counter原始50先保留来源；counter50必须识别实际消费者。区分启动最低条件、实际扣除、恢复延迟、奔跑和回避/爪的不同效果，禁止把50套到所有居合。

建立`AttackDefinition`后恢复审查数值表中的MV与逐段身份。最终伤害需明确拆成物理、属性和异常，按原版顺序和取整规则求值；不把MV直接当HP扣除。第一轮用固定真实攻击、固定斩味/会心、指定肉质和固定颜色的受控木桩，验证各因子与舍入，再扩技能与软化。

居合气刃按动作入口颜色快照选择17／19+55／31+72／39+86及对应shell定义；动画允许继续复用已证明共享骨轨的Native308，但颜色速度与事件不得丢失。登龙使用白10/黄15/红25的七段及属性/部位参数，不再使用统一20。

### 5. 命中、延迟shell与防御

普通攻击由原COL几何、碰撞UID及实际武器/角色骨轨驱动。先证明坐标、骨索引和装备比例，随后对刀刃前后采样做有界连续查询；按动作/碰撞节点/段/目标部位去重。可以分阶段使用有标记的近似，但不能继续把胶囊前方扇区称为刀刃判定。

`HitResult`分开表达接触、合法命中、血量实际变化、弹刀、部位效果与反击回斩，不再靠一个血量差布尔承担全部原生条件。

登龙突刺只授权升空链，不自动授权未来对该目标必中七段。独立研究并实现下劈命中体/标记/附着与延迟结算规则：目标移动、多个部位、多个Actor、目标销毁、障碍和落点必须纳入。标记是否继承到shell、标记在哪个动作生成，按源shell/原生消费者证明，不能反向以现有`HelmMarkedTargets`设计推定原版。

延迟实例使用明确触发原点；首击0.4、后续0.05、上限7与居合0.5秒字段不得混成Land起点后的固定七窗。正常前台派生不应自动等同于撤销已提交实例；实际原版取消/死亡规则逐项取证。结算必须幂等，弱引用失效后安全结束。

防御事件扩展为结构化上下文：攻击ID、攻击者、接触/控制类型、方向、可反击/可回避资格、受击等级。HP伤害、咆哮/风压、震动、持续伤害与强制控制分别消费。保护、反击成功、霸体、减伤和死亡独立求值。普通回避窗及技能扩展另行标定，不用当前0.06..0.4秒自定窗替代原始表。

### 6. 动画连接、运动和装备

对30个LinkMotion节点逐条建立：源条件 → 连接片段/阶段 → 主段入帧 → 输入/碰撞/武器事件映射。当前129→101第48帧是姿态拟合，不等于原版证据；保留为候选，不推及其他连接。

原数据没有提供完整主段入帧时，先解析实际消费者或使用可定位的一手操作录像与源姿态/根运动共同约束；无法确认就保持待标定。禁止“完整connector+完整main”的全长拼接或以最近姿态自动定案。

时钟分清素材坐标、动作模拟时间、游戏世界时间和输入接收时间。现有60Hz换算只是素材转换约定，不是实机60FPS证明。SourcePlayRate、独立武器动画、HitStop、碰撞与资源事件必须具有一致的映射；低帧跨多个事件按原顺序处理，变速键不因帧末才取样而漏算。线性速度插值已有公开实现佐证，保留插值元数据后逐曲线验证，不默认改平方。

登龙保留Rise/Air/Strike/Land结构，替换700/200/1250/3000等初值前先建立参数消费者与单位关系；空中朝向和水平运动按原规则分别控制。逐项验证低顶、斜坡、目标顶部、高落差和不攻击自然落地。

基础移动先把旧库与合格源采样做对照，再迁移待机/行走/跑步，补必要起步、停止、转身、空中和落地状态。不要因`NativeFidelity`目录存在就替换未合格片段。

武器内部轨道、整件装备装配、手掌接触/IK分开维护。0.7比例与固定掌心点保留为适配值，验证后替换；先完成源骨/单位/装配矩阵映射，再逐链移植原始IK约束。接触修正不能让武器瞬间移动并进一步伪造刀刃命中。特殊纳刀73冻结、80事件、等待/超时与纳刀术按原阶段一起解决，不独立强行补触发80帧事件。

### 7. 公共主角状态与完整动作

先补公共状态的控制权和清理，再接动作库：

- 普通/重受击、击飞、倒地、起身、失衡/状态异常、死亡；输入资格、免硬直、可延迟起身及恢复时机各自定义。
- 纳刀/持刀移动、冲刺、四向回避、跌落与地形门控；失去控制时不启动普通地面攻击。
- 投射器/强化射击：弹药、方向/连段身份、I/II/III九个变体及回旋出口。
- 飞翔爪：瞄准/发射/附着、部位切换、耐力、软化/攻击、脱离与失败/目标消失清理。
- 普通空中、颜色跳跃气刃、斜坡/墙面、骑乘；公共动作与武器子图衔接，不能把所有Falling状态当登龙。
- 道具/磨刀/采集/交互/菜单输入上下文；核查现有物品接口后复用，保留效果提交与中断语义。

最后接入原时间轴的刀光、命中、反击、声音、脚步、镜头/震动和停顿。HUD同时显示正确资源和当前合法操作；调试用源码字段与证据标签放开发层，不塞进正常玩家操作流程。

## 风险与回退

- 当前工作区有大量既有未提交/未跟踪资产与源码；实施前按本轮哈希做有范围快照，不能用`git reset --hard`或批量checkout清理。
- 资产迁移以候选DA/Pawn/地图为单位。正式切换前保存每个受影响文件的原字节、源版本及依赖清单；回退仅恢复本轮具体副本，不覆盖用户之后的工作。
- 新反射字段可造成旧DA缺省解释变化；先兼容读取与schema校验，再分批迁移，最后弃用歧义字段。未迁移资产继续运行旧配置并明确标识。
- 独立延迟实例容易造成重复伤害或不当跨死亡存续；必须先确认原版生命周期，再测试执行身份与目标失效。
- 原始输入位/连接消费者可能继续无法完整确认。采用静态证据与可定位一手资料推进可确认部分，保持开放项；不得把人工拟合写成原始参数。
- 坐标/比例/IK改变会同时改变视觉与真实刀刃命中；必须同批验证，不只调整手柄直到单帧看起来贴手。
