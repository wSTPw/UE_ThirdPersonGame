**标准移动 MM 的正式接入被数据质量阻塞。** 直接把已审计原地走跑加入位置/速度轨迹 Schema，会把它们编码成缺乏移动距离的候选。Hips 摆动不能代替真实位移，`measure_natural_speed` 的脚部估计也不能据此伪造 Root 轨迹或转向。可以建立隔离库/ABP 验证技术链，正式替换需另找真实根运动资产或核对原始导出数据。原生角色构造器当前 `MaxWalkSpeed=500cm/s`，与 Run 的估计289cm/s也有尺度差异；蓝图覆盖及真实运行速度尚未在本子任务核实。

根轨迹证据为 `MM-root-Walk_Loop_F_0_Seq_YBot.json`、`MM-root-Run_Loop_F_0_Seq_YBot.json`、`MM-root-Turn_180_R_Seq_YBot.json`；速度证据为 `MM-speed-*.json`。自然速度基于自动接地高度阈值，并非捕捉系统输出的权威真实速度，不能代替视觉脚滑对照。

本机 UE5.8 `PoseSearch/Source/Runtime/Private/PoseSearchFeatureChannel_Pose.cpp` 的默认 Pose 通道采样 `foot_l`、`foot_r`。桥接 `CreatePoseSearchSchema` 注释称默认 Pose 采样 root，与引擎实际构造器不符。且 `AddPoseSearchSchemaPoseChannel` 在构造后的默认 `SampledBones` 上直接追加；`AddPoseSearchSchemaTrajectoryChannel` 同样在4个默认 `Samples` 上追加。仅传入自定义骨名仍留下 Mannequin 默认项，需要读回并整体替换数组。此为静态确认的第三方行为，插件未改。

本地桥接 `ReadBoneTrack` 直接调用 `EvaluateBoneTrackTransform`，未先校验骨名。因此未知骨名得到的默认变换不能作为动画原地播放的证据。默认首、中、尾三个样本也不能排除中途移动后回到原点；决定数据可用性前应按帧抽取稠密轨迹。

`AddMotionMatchingNode` 默认 `connectToOutput=true` 会断开最终 Output 原有链接。对正式 ABP 直接调用会让原 Slot/遮罩链失效。`AddPoseHistoryNode` 默认 `insertBeforeOutput=true` 则在最终链上插入历史节点；具体历史采样位置应在测试副本验证，避免全身攻击污染基础移动搜索。两者都编译并保存目标资产，删除新节点不会自动恢复被断开的原链接。

## 第一步：只读审计

```powershell
python Scripts/Animation/prepare_motion_matching_audit.py --output Saved/ActionRefactor-20261019/MM-audit-requests.json
```

通过正常 UE-MCP 网关逐个执行 JSON 中的 `readOnlyRequests`。首轮用 `animation.read_sequence` 取得六条序列 `skeleton`、长度、通知和 Root Motion 开关与 ABP 图，再调用 `animation.get_bone_transforms({skeletonPath: 实际Skeleton})` 确认根骨与双脚。随后把已核实值作为脚本 `--skeleton-path`、`--root-bone`、`--foot-bones` 参数，生成第二轮轨迹与速度读取请求；不能直接照填 Mannequin 骨名。本轮已核对网关命名；`read_anim_sequence` 是 C++ handler 内部名，网关曾明确返回 UNKNOWN_ACTION，脚本已修正。

`read_bone_track` 的 `frames` 可指定从 0 到结果 `numFrames` 的整数数组，以检查实际局部根轨迹。`sample_pose` 可用 `boneNames`、`space:"component"`、`incorporateRootMotion:true` 核对父层变换后的脚部运动。`measure_natural_speed` 的速度来自脚部接触估计，仅作为标定依据，需核对输出接地样本质量。不要只打开 EnableRootMotion；它不能创建缺失轨迹。

## 第三步：测试 ABP 与图连接

1. `asset.duplicate` 使用 `sourcePath:"/Game/MyStuff/Model/Robot/ABP_Move"`、`destinationPath:"/Game/MyStuff/Animation/MotionMatching/ABP_Move_MM_Test"`、`onConflict:"error"`。读取副本 AnimGraph，保存真实节点 GUID、引脚名、Slot 与骨骼遮罩连接。
2. 在副本调用 `animation.add_motion_matching_node`，设置 `connectToOutput:false`、`databasePath:新Database`、`blendTime:0.2`。调用 `animation.add_pose_history_node` 时先设置 `insertBeforeOutput:false`、`generateTrajectory:true`、`poseCount:16`、`samplingInterval:0.033333`；通过真实图连接决定插入位置。
3. 用 `blueprint.connect_pins` 的真实 `sourceNodeId/sourcePin/targetNodeId/targetPin` 接入副本的基础移动分支，保留 Attack、UpperBodyOnly、跳跃/空中分支和原武器姿态选择。不能猜测 Output/Source 引脚名；读图后再连接。历史节点必须包住 MM 可查询的姿势链。
4. `animation.inspect_anim_nodes` 读回 `MotionMatching` 与 `PoseSearchHistoryCollector` 的节点结构，核对实际 Database、历史轨迹设置和 Blend。UE5.8 Motion Matching 的 `bUseInertialBlend` 默认 false；若改为 true，须有后续 Inertialization 节点，不能只设置 BlendTime 就假设惯性混合已启用。
5. 复制测试角色引用副本 ABP；原 BP_MyPlayer 的正式引用暂时保留。Pose History 自生成轨迹是最小原型选项，尚不等于方案 `FLocomotionAnimContext` 已实现；必须验证动作锁定时预测使用受约束的实际运动，不使用仍按住但已禁止的输入意图。

## 验证与回退

原型至少覆盖走跑切换、急停、左右90/180度转向、横移、撞墙、攻击/喝药前后、换武器、不同帧率。单长剑库不能在空手或法杖姿态下无条件使用。确认攻击6命中、火球与物品 Commit 次数没有因图接管而变化；记录选帧抖动、可见脚滑、Montage 返回跳变、AnimGraph/PoseSearch CPU 和索引内存。未完成这些运行对照前，P5 保持待验证，不标记正式接入。

回退只需取消测试角色对副本 ABP 的引用并重启 PIE；原 ABP 没有被修改。删除副本节点前应保存完整图连接快照，避免误把节点删除当成原连线自动恢复。第三方桥接源码未改。
