## 三、修订路线（Phase 0–4，替代原 M0–M6 的推进顺序，阶段门保留）

| 阶段 | 内容 | 验收门 |
| --- | --- | --- |
| P0 安全基线 | 工作区未提交修改归档（用户已有工作与项目新增分开提交）；固定原始资源 hash/工具版本/构建配置 | 从干净工作区可恢复并构建 |
| P1 fexty 复用与可达动作清单 | ① 27 类映射逐项参数形态校验（已完成首轮，见覆盖 JSON）；② 用 0xB8(rank) 门控从 THK 建立**下位可达动作清单**；③ 输出已知/冲突/未知三栏映射表 | 首轮所需语义与动作清单冻结（不再全量 344） |
| P2 核心战斗闭环（B1+执行层统一） | 决策器只决定"做什么"，动作执行（动画/位移/碰撞窗/伤害/结束）由**同一套 ActionSpec** 驱动；B1 补搜索/发现/转向/接近/咬击/冲撞/尾击/喷火/怒/疲 | 连续战斗可切换状态、打断正确 |
| P3 原作对照测试 | 固定任务/装备/无覆盖条件；每帧/每事件对照字段（state/thk node/condition/result/distance/action/bank/slot/pos/hitbox/damage）；未观测字段写 unobserved，不填推测 | BITE 第一份可复现差异报告 |
| P4 忠实度扩充 | 下位可达动作全量、部位破坏、取整、异常、关键音画（优先咬击命中/火球/吼叫/落地四类）；逐项回归 | 首个下位单人验收配置 |

### ActionSpec（P2 引入，采纳评审建议）

每个关键动作一份：动作资格（THK 条件引用）、前置转向、动画（bank/slot/资产）、位移、碰撞窗、伤害事件、可打断时机、结束条件；每字段带五维证据标注。B1 与未来 ThkPolicy 共享同一 ActionSpec，禁止两套执行逻辑。

### 动作覆盖口径

- 弃用"344 条全覆盖"目标；改为 **目标任务内可达动作覆盖率 = 已验证动作数 ÷ 实际可达动作数**（由 0xB8 门控 + THK 调用图确定分母）。
